# The Over-Engineered Decision Maker

A responsive, single-page mission-control dashboard for completely ordinary choices.

## Run

Requires Node.js 20.11 or newer. No installation or API keys are needed.

```sh
npm start
```

Open http://127.0.0.1:4173. Serve the `dist` folder with any static web server for deployment. ES modules require HTTP; double-clicking `index.html` is not supported.

The `dist/` directory contains the maintained application source and vendored browser libraries, so it is intentionally versioned. Dependencies, disposable build folders, environment files, logs and local hosting/editor metadata are excluded by `.gitignore`.

## Production deployment (Vercel)

The Git repository root is the app directory containing this `package.json` and `vercel.json`. Keep Vercel's Root Directory empty, select the Other framework preset, and deploy `main`. The versioned configuration explicitly uses `npm ci`, `npm run build`, and the `dist` output directory. This is a static browser app; `server.mjs` is only the local preview server.

```sh
npm ci
npm run build
npm test
```

The build checks JavaScript syntax, regenerates Tailwind CSS, and verifies the entry point and every local HTML/ES-module dependency. It preserves the maintained `dist` source. Extensionless paths fall back to `index.html`, while real assets retain their correct MIME types and missing asset files return 404 rather than HTML. The HTML base URL ensures nested paths load scripts, styles, and the Three.js import map from the site root. Unversioned assets revalidate on reload instead of receiving immutable caching.

Only navigation, optical/timezone preferences, and archive history persist. Live inputs and simulation/combat/trial state remain empty after reload, including on nested SPA paths.

## Features

- Three.js 3D topology with OrbitControls, projected labels, node hover metrics, view reset, and rotation pause.
- 10,000 paired Monte Carlo outcomes per run, with genuine mean, median, standard deviation, lower-tail percentage, histogram, and Wilson 95% confidence interval.
- Weighted 3×3 risk heatmap with context-aware fictional threats and accessible, focusable markers.
- Web Audio hum, processing sequence, and completion drop/chime. Audio starts after a user gesture; mute affects all sounds.
- High-performance mode reduces particles from 1,200 to 150 and limits rendering to 30 fps.
- Responsive layout, keyboard controls, reduced-motion support, and a numerical fallback if WebGL is unavailable.
- Five grouped decision categories with fourteen contexts, domain-specific factors and threats.
- Blank inputs on every page initialization or reload, a neutral matrix idle state, and ambient graph pulses until the first valid run. Live choices are shared between modules only for the current page session.
- Randomized, accessible hazard alerts for blank or semantic duplicate options, including casing, trailing punctuation, and regular singular/plural variations. Invalid input never starts a simulation; acknowledging the warning focuses the input to correct.
- Optical Mode switches between Deep Space and Solar Diagnostic, including the 3D scene, chart axes, tooltips and risk heatmap. The selected mode persists across refreshes.
- The plain header timezone label cycles UTC -> IST -> GMT on click, touch or keyboard activation, without popovers, brackets or animations. With no saved preference, the browser region/offset automatically selects IST, GMT or UTC. UTC/GMT use +00:00; IST uses +05:30. Selection updates immediately and persists across all modules and reloads in `oddm_user_timezone`.
- Solar Diagnostic uses a Clinical Tactical HUD: sterile white surfaces, teal controls, teal/violet distributions, five semantic node colors, faint grid lines, crosshair threats and a pulsing idle directive.
- Desktop dashboard uses a 3/5/4 column split: mission controls; Executive Directive above the 3D graph; probability, risk and telemetry. On screens below 1024px, the verdict leads the stacked layout, followed by controls, graph and analytics. Running the matrix reveals the banner when off-screen and triggers processing/completion effects. Document scrolling remains unrestricted.

- Four working tactical tabs: Quantum Matrix [01], Option Fighter II [02], Quantum Trial [03] and Black Box Archives [04]. Navigation terminates at Archives.
- Shared page headings use the same 40px, weight-800 sans-serif title, 12px breadcrumb and aligned desktop content offset in both themes. The selected tab persists across reloads in `oddm_active_tab`; live inputs and simulation/court/combat state still start blank or idle.
- Black Box Archives saves each completed Matrix run, then attaches its completed three-round tournament and judicial decrees. The unified dossier includes explicit skipped-stage badges, probabilities, utilities, combat telemetry, sworn testimony, a randomized universal alternate timeline, print/save-PDF and plain-text export. Archive purge requires confirmation.
- Quantum Trial always has read-only Matrix choice fields and requires a completed, valid Matrix simulation. Six inline courtroom banners handle empty, partial, identical, plural and unrun choices. Its indictment uses the explicit simulation winner/loser, with randomized phrasings, reroll, eleven sarcastic charges and a classification gate. Each case draws three unique questions from ten and three shuffled responses per question, with classified prediction badges by default. It includes live outrage/commentary, procedural gavel/alarm effects, independently randomized tier-specific decrees and sentences, appeal resets and certificate preview/export.
- Option Fighter II is a canvas arcade tournament with player-vs-AI or autonomous AI, animated vector fighters, plasma specials, blocking, combos, KO effects, three distinct arenas, glowing win pips and a series-champion Matrix/Trial handoff.

## Source

`dist/engine.js` owns the fictional utility model and statistics. `dist/contexts.js` defines categories, factors and threats. `dist/validation.js` shares input validation between the form and engine. `dist/topology.js` owns the 3D scene and smoothly updates node scales, positions and edge opacity from each run's weights. `dist/audio.js` synthesizes audio. `dist/app.js` coordinates UI state, charts, and logging. `dist/styles.css` defines the dashboard. Tailwind is compiled to `dist/tailwind.css`; Lucide, Chart.js, and Three.js are locally vendored in `dist/vendor`.

To regenerate Tailwind after editing utility classes, run `npm ci` and `npm run build:css`. This is optional for running the shipped app.

Both options use identical random processes. Each run draws fresh independent means from a symmetric distribution around 50 and generates 10,000 paired outcomes with fresh `Math.random()` draws. Names and context never affect scoring or favor a position. Either option has an equal chance of winning across runs; consecutive swaps are possible, not forced.

Chaos controls base standard deviation (`2 + chaos × 0.28`) and heavy-tail shock probability (`0.24 × (chaos / 100)²`). Scores are unclipped abstract utilities, so high chaos produces genuine extreme outliers. Histogram bins cover both complete sample ranges. The graph's four weights represent volatility, lower-tail risk, average threat exposure and winner frequency; every valid run replaces all result data.

The simulation is entertainment. Its confidence interval estimates win frequency under the fictional model, not real-world certainty. Regret is the simulated losing fraction of the recommended option. Risks are procedurally generated independently of the outcome samples.

`dist/theme.js` applies a saved `decision_maker_theme` before styles load, otherwise follows the system preference until a mode is explicitly selected. Storage failures leave the toggle usable. The optical badge is fixed at 210×36px across both themes and all breakpoints, with a 16×16px icon slot and a centered 126px label slot. Both labels and inline SVGs exist in the HTML; root theme CSS chooses the correct pair before the first paint, without delayed text replacement or Lucide conversion. Parser boot synchronizes its accessible name/pressed state; theme changes keep them synchronized. A stable scrollbar gutter prevents the header's right edge shifting when scrollbars appear. Screens below 360px stack header controls while retaining the badge dimensions. `dist/theme-palette.js` shares canvas colors; CSS variables style the panels with 300ms color transitions, suppressed during startup. Tailwind 4 uses a class-based `dark` custom variant, equivalent to `darkMode: 'class'`. Theme changes preserve simulation data and update existing renderers without reload. The local server disables caching so refreshed pages load the latest edits. See `OPTICAL_LOCK_VERIFICATION.md` for measured bounds and delayed-load checks.

`dist/clinical.css` contains the Solar-specific component rules. See `CLINICAL_THEME.md` for the exact tokens, Tailwind utility equivalents, semantic Three.js node mapping and Chart.js update hooks.

`dist/layout.css` defines the command-center columns and substantial verdict card: 20–24px padding, tactical corner brackets, status badge, pulsing radar, large monospace option name, separate win-rate/95% interval metrics and an 8px regret bar. Solar uses `#f0f9ff` with a `#0284c7` border; Deep Space uses `#0c1929` with glowing cyan framing. Long option names grow the card naturally.

The grid uses `grid grid-cols-12 gap-4`, with `lg:col-span-3`, `lg:col-span-5` and `lg:col-span-4`. All three desktop columns stretch to the shared row height. The center is a full-height flex column with an auto-height verdict and `flex: 1` topology panel (minimum 420px). Its canvas container has a zero minimum height and fills the remaining space; the existing Three.js `ResizeObserver` updates renderer size and camera aspect whenever that space changes. The right telemetry panel flexes to finish at the same bottom border. Phones/tablets use natural stacked heights instead. Existing element IDs preserve renderer and simulation updates.

`dist/validation.js` shares normalization and routing between the form and engine. Missing input is handled first; trimmed, case-insensitive identity then precedes the plural-only `isPluralMatch` check. Punctuation-only differences also use the identity branch, preserving trailing-punctuation validation. Plural matching supports symmetric `s`/`es` additions, `y → ies`, and equal suffix-stripped stems longer than three characters. `isSemanticDuplicate` remains available as the combined helper. Punctuation-only choices count as missing input.

`dist/navigation-preference.js` runs synchronously in the head and restores a valid numeric tab ID (`01`–`04`) from `oddm_active_tab`, falling back to Matrix when the key is missing, invalid or unavailable. The root view marker controls both panel layout and navigation glow through exact module equality before first paint. HTML has no default active tab or panel visibility. The parser-blocking `dist/navigation-boot.js`, immediately after the navigation markup, sets ARIA selection, tab stops and mobile strip position before deferred app code loads. `dist/navigation.js` retains that same state without activating unfinished controllers. A root `preload` class suppresses transitions; main content reserves the selected layout but becomes visible only once controllers, empty-state warnings and archive data are initialized. `dist/app.js` then releases transition suppression after two animation frames, independently of optional Three.js loading. Clicks, keyboard navigation and correction/return CTAs all save the destination tab. Storage errors preserve in-session routing. This preference never reads or writes options, simulation results, combat locks or court state. Reloading restores the page while those live values reset. Archive history and optical/timezone preferences remain independent. See `FLICKER_FREE_VERIFICATION.md` for delayed-load first-frame evidence.

Navigation hides panels without replacing their DOM, so live inputs, settings, telemetry, charts and completed or ongoing simulations survive ordinary tab changes. `dist/navigation.css` defines spectrum-specific tab colors. `dist/module-header.css` is the shared header contract for all four views: Barlow/Arial sans-serif, 40px/1.1, weight 800, -0.02em title spacing, identical 10px/12px title margins and 32px vertical header padding. Breadcrumbs use 12px/1.5 monospace, weight 600 and 0.08em tracking. Descriptions reserve two lines to align desktop content starts; mobile titles use 32px and natural wrapping with 24px padding. Archive-only title typography/top spacing and the fighter's italic/skewed title treatment are superseded by this shared contract. See `HEADER_NAVIGATION_VERIFICATION.md` for measured browser evidence.

`syncModuleActivity()` in `dist/app.js` updates each working module on module and document-visibility changes. Pausing cancels the outstanding animation frame, and resuming resizes the existing renderer before scheduling a single loop. No new WebGL context or Chart instance is created when switching modules. Audio is suspended when the document is hidden or Archives is selected; returning to Matrix resizes the retained probability chart. Browser page-cache restoration also restores the appropriate activity state; final page teardown disposes the renderers normally.

The separate immutable `EXACT_MATCH_ERROR_POOL` and `PLURAL_MATCH_ERROR_POOL` each contain four templates. Identity faults show `[ERR 400: IDENTITY PARADOX DETECTED]` and **ACKNOWLEDGE MY HUMANITY**, then focus Option A. Plural faults show `[WARN 409: SEMANTIC PLURALITY DETECTED]` and **ACKNOWLEDGE & RE-INPUT**, then focus Option B. Every fault replaces all modal state. Placeholder insertion capitalizes each displayed word, preserves literal replacement characters, and uses text content; valid verdicts retain the original input spelling. Blank input keeps its own warning pool and focuses the missing field. `dist/alerts.css` supplies the hazard palette, pulse and backdrop blur.

Run `npm test` for 89 regression tests covering Matrix validation/simulation, volatile shared choices, optical/timezone preferences and parser-time accessible header binding, court gates/question sampling/decree tiers, all tournament outcomes and dual-theme stages, archive aggregation/persistence, and saved-tab initialization, parser-time selection/mobile scroll, routing, invalid preferences and unavailable storage. `npm run check` checks JavaScript syntax.

Google Fonts is optional; system fonts provide an offline fallback. All functional dependencies are bundled locally. Third-party license notices are in the vendor files and `THIRD_PARTY_NOTICES.md`.

## Quantum Trial // Module 03

The third tab opens a scripted AI Kangaroo Court. Its native Option A/B fields are always read-only and retain the Matrix input order. Only a completed valid Matrix simulation authorizes a dossier; the six inline legal banners evaluate both empty, A missing, B missing, normalized identity, plurality and missing/coherency-invalid simulation evidence, in that order. Classification is disabled and the dossier/surrender button are hidden while blocked. Each banner routes to Matrix and focuses Option A, Option B or Run as appropriate. If a run is still computing, Run receives focus as soon as it is enabled. No error modal is opened.

`dist/trial-validation.js` shares the Matrix normalization/plural helper and owns the provided legal warning messages. `generateIndictment` maps `{winningOption}` and `{losingOption}` to the explicit `matrixState.winner` and `matrixState.loser`; it never assumes Option A won or uses arena provenance as simulation evidence. Thus sushi / pasta with a B win indicts picking pasta over sushi while the fields remain sushi / pasta. Select a legal charge, surrender to the tribunal, and answer three questions. The dropdown contains the eleven supplied charges plus an unselected placeholder (twelve entries total); surrender is disabled until a valid charge is chosen. Each answer changes public outrage and appends the exact supplied human, prosecution and defense testimony, plus designated and applied jury deltas. Outrage is clamped to 0–100% after every answer. See `TRIAL_LOCK_VERIFICATION.md` for current end-to-end checks.

`dist/trial-bank.js` holds all ten questions and 31 responses, plus three immutable decree tiers. Fisher–Yates shuffling selects three unique questions and three unique randomized responses per question; the four-response research question omits one at random. Sampling happens only at case start, and the selected questions, response order and testimony are sealed for navigation and certificates. The toolbar's **REVEAL JURY PREDICTIONS** checkbox starts unchecked. Option buttons then show **SWORN TESTIMONY**, **RECORDED FOR TRIBUNAL** or **IMPACT CLASSIFIED** badges. Checking it reveals the precise signed outrage deltas; changing it only updates badge text, preserving focus, response order and disabled states. This preference is in memory only and resets on reload. The current jury meter and already-recorded testimony remain visible.

Final outrage 0–25 selects the Low tier, 26–65 selects Moderate, and 66–100 selects Extreme. A headline (three per tier) and mandatory sentence (four per tier) are drawn independently when the third answer resolves. Low cases are acquitted/pardoned; both other tiers are guilty. The exact disposition and sentence remain stable through theme changes, navigation and export. T3 identifies the tier explicitly. See `TRIAL_BANK_VERIFICATION.md` for current live cases and threshold checks.

`dist/options-state.js` owns the volatile shared immutable choice snapshot, within 60-character name limits. Every page creates an independent instance with empty choices, null combat winner/loser and `matrixState` initialized to `hasRun: false`, null winner/loser and null run ID. There are no decision-storage reads, writes or cleanup hooks; legacy saved choices are ignored. Only Matrix inputs update the pair. Changing either choice clears both simulation evidence and the combat lock. Starting a new simulation clears eligibility immediately; completing it publishes the explicit winning name, losing name and unique run ID. Epoch tokens reject stale completions, including choices edited away and back.

Round 3 still publishes the overall arena champion/runner-up to the separate combat record. Applying the champion updates choices and the arcade directive atomically: a changed pair invalidates Matrix evidence, while an unchanged pair retains the actual simulation winner even if combat chose the opposite option. Combat alone cannot authorize Trial. Reloading or reopening resets live choices, simulation evidence, combat provenance, classifications, outrage and directives. The active tab, historical archive snapshots, Optical Mode and header timezone preference remain saved. Archives never restore choices or authorize a live trial. See `SESSION_VERIFICATION.md` for historical session checks, `TRIAL_LOCK_VERIFICATION.md` for evidence rules, and `HEADER_NAVIGATION_VERIFICATION.md` for current reload behavior.

`dist/time-zone.js` exports the root `siteTimeZone` singleton. Valid saved preferences (`oddm_user_timezone`) take precedence; otherwise browser Intl region and UTC offset detection initialize and save IST, GMT or UTC. The plain header abbreviation cycles UTC -> IST -> GMT -> UTC on click or native keyboard activation, with immediate global clock updates and reload persistence. `dist/header-clock.js` stays mounted during module navigation. Its CSS inherits the clock typography and uses a fixed-width, borderless, transparent button with no animations. All former arc/popover markup, hover listeners, vector overlays and layout reservations are removed. See `TIMEZONE_VERIFICATION.md` for checks.

`generateIndictment` in `dist/trial-engine.js` selects one of six supplied templates and inserts the completed simulation winner/loser in a single pass, preserving literal punctuation, dollar signs and token-like text. Invalid evidence is rejected without constructing a generic dossier. Reroll changes structure without changing the recorded winner, loser or charge. Navigation retains the phrasing and active case while the same run remains valid. Editing Matrix choices or beginning another run cancels the old trial, clears transcript/certificate state and pending gavel/question timers, and returns to the inline evidence gate. A new result produces a fresh dossier; restoring old text alone cannot restore its old authorization.

`dist/trial-engine.js` owns the guarded three-phase state machine, case sampling and exact answer weights from the bank. Each answer stores the sampled question ID/text, all four supplied response fields, requested delta and clamped applied delta. `dist/trial.js` renders the court, prediction badges, finite gavel transitions and transcript, shared procedural audio, appeal resets, and certificate preview/download. `dist/trial.css` provides both optical palettes, responsive layouts, reduced-motion support and print rules scoped to an open certificate. No additional canvas or animation loop is created. Switching tabs preserves trial and Matrix state; hidden Matrix topology is paused.

Appealing clears classification, questions, answers, outrage, transcript and decree, generates a fresh dossier from the latest Matrix choices, disables surrender and focuses the classification selector. The next surrender samples a fresh examination. The prediction-reveal preference lasts for the current page session. Certificates use the completed case snapshot and contain the actual sampled question/answer pairs, tier, disposition and mandatory sentence. The preview can print/save as PDF or download a standalone, escaped HTML document. Low-tier cases receive a Certificate of Tribunal Acquittal; the button and seal match the outcome. The trial is entirely local and scripted; it requires no AI API or network request.

The completed decree includes **OPEN BLACK BOX ARCHIVES [04]**, which opens its linked dossier. See `TRIAL_VERIFICATION.md` for historical courtroom verification and `ARCHIVES_VERIFICATION.md` for the current complete pipeline.

## Option Fighter II // Module 02

The arena automatically loads Matrix choices at initialization and when idle choices change. **LOAD MATRIX OPTIONS** manually re-syncs custom names (maximum 60 characters each). Both Matrix choices must be nonblank and lexically distinct: otherwise initiation is disabled, even if custom arena names are supplied. `dist/fighter-validation.js` distinguishes both-empty **VOID COMBAT**, only-A **SOLITARY SHADOWBOXING**, and only-B **UNOPPOSED GLADIATOR** warnings, with the provided name inserted literally. The warning button names the missing input: **INPUT BOTH OPTIONS**, **INPUT OPTION A**, or **INPUT OPTION B**. It routes to Matrix and focuses that field (Option A when both are empty). Exact duplicates show **ERR 422: TAUTOLOGICAL COMBAT PARADOX**; regular plural variations show **ERR 418: GRAMMATICAL DUPLICATION DETECTED**. Identity precedes plurality, using the same normalization and plural helper as Matrix. Both conflict CTAs focus Option B; Fighter errors use the native banner without opening a modal. Providing two distinct choices hides the banner. Choose **PLAYER VS AI** or **AUTONOMOUS AI VS AI**, then initiate combat. A named VS splash, teleport beams and round callout precede the 60-second duel. Names have no effect on combat strength; both autonomous fighters use the same AI rules with fresh randomness.

Player A uses **A/D** or arrows to move, **W/↑** to jump, **S/↓** to crouch/block, **J/Z** for a 10-damage jab, **K/X** for a 22-damage sweep, and **L/C** for a charged 40-damage special. Blocking reduces damage by 75%. A special requires 100% Overthink charge and pauses combat briefly; A launches plasma, while B performs an energy uppercut. **P** pauses/resumes. Pointer controls support touch movement, blocking and attacks. Optional announcer speech depends on the browser's installed voices; procedural Web Audio effects work independently and share the suite's mute setting.

`dist/fighter-engine.js` owns movement, collision, attack windup/recovery, AI, meter gain, combos, timer and guarded round transitions. It keeps `currentRound`, `winsA`, `winsB` and immutable completed-round reports in `roundHistory`; the final `seriesReport` is separate from the last round's report. `dist/fighter-renderer.js` caches each arena's background and draws articulated fighters, reactive lighting, vehicles, beams, projectiles and bounded particles. `dist/fighter.js` owns one animation loop with a fixed 120 Hz simulation and 10 Hz HUD updates; `dist/fighter.css` supplies both optical palettes and responsive controls. The arena preserves a 16:9 aspect ratio and caps its drawing buffer at 1280×720 to bound GPU cost. Render FPS follows the display/browser; no frame rate is guaranteed on every device. Reduced-motion preferences disable shake/flash and reduce particles.

KO plays a 1.5-second 0.2× impact sequence, loser pixel disintegration and winner aura/pose. Timeout awards the fighter with more health; equal health uses a random tiebreak. Every tournament plays all three rounds, including at 2–0. Each round resets health to 100, Overthink to 0 and the timer to 60 seconds, while retaining wins and history. Three pips beside each callsign fill cyan for A or rose for B as rounds are won.

`dist/fighter-stages.js` defines the immutable `ARENA_ROUND_MAP` registry with `RoundStageConfig` / `StagePalette` JSDoc types. `getActiveRoundStage(round, isDark)` safely clamps the round and selects one of six environment configurations. Round 1 is **NEON CITADEL** / **BLUEPRINT METROPOLIS**: a layered midnight city with shaped spires, cyan/magenta windows, beacons, rising data pillars and cyan atmospheric bloom versus a precision slate CAD skyline with crosshairs, drafting circles, dimensions and elevation marks. `dist/fighter-cityscape.js` isolates its cached architecture and bounded animation. Round 2 is **NEURAL SYNAPSE MATRIX**: violet neural nodes and traveling electric pulses in Plasma Web versus opal-white clinical containment rings, amber sweeps and terracotta telemetry in Clinical Cleanroom. Round 3 is **SINGULARITY COURT**: a fractured crimson core sphere emitting red bursts in Event Horizon versus a mechanical containment ring, high-vis warnings and coral vectors in Solar Flare Sector. Both final environments carry black/yellow floor hazard stripes and CRITICAL DECISION OVERLOAD signage.

Every render frame resolves the current combat round and central root `.dark` signal. Round/theme changes rebuild static scenery offscreen; ordinary frames reuse it. Next-round banners crossfade cached scenery for 650 ms using the existing intro clock, finishing before combat begins. Reduced motion skips this fade. Theme switches are immediate, including during a fade: the old environment is dropped instead of allowing an old theme or round to leak through. Neural pulses, clinical radar sweeps, core bursts, floor distortion and warning lines animate separately from physics. The central optical event also requests a zero-delta repaint for paused matches, preserving diagnostic hitboxes. Theme changes never restart RAF, advance/reset engine state, consume combat RNG, clear controls or dispatch audio/verdict events. See `METROPOLIS_VERIFICATION.md` for current Round 1 checks and `ROUND_STAGE_VERIFICATION.md` for unchanged Round 2/3 checks; older Round 1 evidence describes superseded concepts.

After Rounds 1 and 2, both the arena overlay and F2 offer **PROCEED TO ROUND 02 // 03** or **PROCEED TO ROUND 03 // 03**. Setup is locked between rounds to preserve the contestants. No Trial or Apply action is exposed yet. After Round 3, the majority champion receives **K.O. // TOTAL DOMINANCE ACHIEVED** for 3–0 (one of three randomized sweep headlines) or **DECISION // MAJORITY WIN** for 2–1. The badge shows `ROUND 3 // SERIES A-B`. Mid-round telemetry covers that round; final telemetry sums damage across all three, takes the largest combo and calculates signed-meter volatility across the full series. Champion integrity is explicitly its most recent winning round's remaining health. The three history cards retain each individual winner, integrity and duration. **RESTART 3-ROUND SERIES** clears the score/history and starts a fresh Round 1 with the same fighters; **NEW CHALLENGERS** restores setup. See `TOURNAMENT_VERIFICATION.md` for current checks.

**APPLY WINNER TO QUANTUM MATRIX** becomes available only after Round 3. It copies both names and sets an explicitly labeled tournament-champion directive with the series score. Previous Monte Carlo analytics remain intact and are identified as the last simulation; combat results do not manufacture a probability or confidence interval. Running the Matrix again replaces the combat directive with fresh statistics. Applying is disabled while the Matrix is calculating.

**PROCEED TO QUANTUM TRIAL [03]** appears in the victory banner and result actions only after Round 3. It opens Trial, which requires completed Matrix evidence independently of combat. Without it, the court displays the Run-required banner. With valid Matrix evidence, the indictment cites its actual simulation winner, regardless of the arena champion. Ordinary tab navigation preserves a case while its Matrix run remains valid; explicit Proceed resets it to the dossier stage. See `TRIAL_LOCK_VERIFICATION.md` for current Trial rules and `TOURNAMENT_VERIFICATION.md` for arena round checks.

Leaving the module or hiding the document cancels its animation frame and clears held controls; returning resumes the same match. Manual pause is retained. Losing window focus additionally pauses player-controlled matches; autonomous matches do not require operator focus. Matrix and Trial remain mounted with their state intact. See `FIGHTER_VERIFICATION.md` for checks and screenshots.

## Black Box Archives // Module 04

`dist/archive-engine.js` owns `BlackBoxStore`, `ArchivePipeline`, the dossier summary/text generators and eighteen universal alternate-timeline templates. The versioned localStorage envelope at `oddm_blackbox_archives` contains monotonic `CASE-0001` IDs, timestamps, compact Matrix snapshots, and arrays of completed combat/trial attempts. Raw 10,000-sample arrays are not persisted. On reload, archive snapshots are validated independently of the volatile live modules. Denied/full storage falls back to session memory with a visible notice and text export; unreadable records are excluded, and damaged optional stages cannot erase valid Matrix evidence.

Each successful Matrix run creates its case immediately. At combat or trial start, an immutable ticket captures that case ID and the baseline pair. Completion appends to the originating record, even if a newer run exists. Custom fighter names and combat without a prior valid Matrix run cannot fabricate stage evidence for an unrelated case. Only a completed three-round series seals Stage 02; only the third sworn answer seals Stage 03. Repeated completion events are idempotent. Rematches and appeals retain previous attempts, with the latest completed telemetry shown in the report.

`dist/archives.js` renders the read-only repository and native dossier/confirmation dialogs. Missing stages remain prominently marked **STAGE BYPASSED**; a full dossier requires both combat and trial. The final declared winner uses the completed tournament champion when available, otherwise the Matrix recommendation. Both names remain separately labeled when the modules disagree. Regret remains the original Matrix estimate, independent of jury outrage. Combat reports include aggregate active fighting time and damage, all round winners, final resolution, champion last-win HP and actual final-round HP, which may differ.

Opening a dossier draws a new lighthearted universal alternate outcome using the final runner-up. That statement stays fixed for the current view and its text export. User names are inserted literally using text content. **PRINT DOSSIER / SAVE PDF** uses the browser print dialog with report-only paper styling; **EXPORT DOSSIER (.TXT)** downloads the viewed evidence and alternate outcome as a monospace-friendly log. Export object URLs are released on close, refresh and teardown. **PURGE ARCHIVE LOGS** opens a confirmation with Cancel focused; confirming removes historical records while keeping the case sequence monotonic, so pending old stage tickets cannot attach to a reused ID. `dist/archives.css` provides both optical palettes, glass panels, a locally scrollable mobile table and responsive/print dossier styles. See `ARCHIVES_VERIFICATION.md` for the live browser evidence.
